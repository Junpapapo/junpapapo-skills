🚨 IEEE 1044 / ISTQB Software Severity Standards

Standard criteria for classifying issue criticality and SLA response priority.
🚨 S1 Blocker Immediate Fix (P0)
S1 Blocker (Showstopper)
App crash, infinite freezing/deadlock, data loss/corruption, payment failure, or app store review rejection. Critical user journeys are completely blocked with zero workarounds.
🔥 S2 Critical Urgent Fix (P1)
S2 Critical (Severe Defect)
Core business logic defect, cloud sync loss, notification/permission failure, or significant feature breakdown without a viable workaround.
⚡ S3 Major Sprint Priority (P2)
S3 Major (Standard Defect)
General feature bug or edge case error where a reasonable workaround exists. State sync delays or abnormal gesture responses.
🌱 S4 Minor Polishing (P3)
S4 Minor (Cosmetic Defect)
UI padding/alignment deviations, dark mode contrast issues, typos, or minor text overflow/clipping without functional impact.
☕ S5 Trivial Maintenance (P4)
S5 Trivial (Refactor / Hygiene)
Code readability refactoring, unused variable cleanup, 400-line modularization, and architectural governance for maintainability.
💡 Tip: When registering via CLI (add_issue.py), severity is automatically inferred if --severity is omitted.
